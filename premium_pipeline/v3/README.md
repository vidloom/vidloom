# Vidloom v3: evidence before editing

Start with [GEMINI_PROMPT.md](GEMINI_PROMPT.md). The complete production method is
[EDITORIAL_PLAYBOOK.md](EDITORIAL_PLAYBOOK.md); sources and the previous edit's
failure analysis are in [RESEARCH.md](RESEARCH.md).

See [WORKED_EXAMPLE.md](WORKED_EXAMPLE.md) for an evidence-first food concept,
including how to reject missing footage and align an actual spoken claim.
Use `experiment.template.json` for post-publication observations.

This is a new, opt-in pipeline. Earlier renders and v1/v2 scripts are preserved.
Do not use their proportional shot weights, line-by-line narration or estimated
caption timing for v3 projects. No video is generated by validate or plan.

## Workflow

Run commands from the repository root. Use a new project directory. Copy the
template and fill it from actual observations; it intentionally fails validation
until populated. `schema.py` is the strict schema source. Print its JSON using:

```bash
python3 premium_pipeline/v3/pipeline.py schema
python3 -m pip install -r premium_pipeline/v3/requirements.txt
python3 premium_pipeline/v3/pipeline.py probe /absolute/path/to/source.mp4
```

1. Read the playbook; write `brief.md` containing three candidate ideas and why
   the selected one is worth watching. Inspect available footage before scripting.
2. Populate assets/observations and a coverage table in `evidence.md`. Fill brief
   and connected script in your `project.json`. Missing proof blocks production.
3. Record/import a complete narration take, or use the optional local command:

```bash
python3 premium_pipeline/v3/pipeline.py take path/to/project.json --voice af_sarah
```

This performs one Kokoro `create` call using the existing local model. It does not
render video, cut sentences, trim internal pauses or choose a different engine
on failure. One call does not guarantee natural prosody; listen before acceptance.
Use a new filename for a new take. Never overwrite a reviewed recording.

4. Align that take. Optional WhisperX runs in a separate compatible environment;
   consult its current README before installation (the host uses Python 3.14,
   which may not suit all alignment dependencies). Example after installation:

```bash
whisperx /absolute/path/to/take_01.wav --model large-v3 --language en --output_format json --output_dir /absolute/path/to/alignment
python3 premium_pipeline/v3/import_alignment.py /absolute/path/to/alignment/take_01.json /absolute/path/to/voice/words_01.json
```

ASR output must match the actual recording and approved script. Listen to and
correct word boundaries. Words without alignment stop import. For manual
listening-based alignment, set `alignment_method=manual_listened` and supply:

```json
[{"word":"Example","start":0.12,"end":0.48}, {"word":"only.","start":0.5,"end":0.95}]
```

Those numbers illustrate the format; never copy them into real alignment.
Numbers should be written as spoken in the script, so transcript comparison can
work. Do not "repair" a transcript mismatch by changing timestamps without listening.

5. Place each beat and shot against aligned words, then add captions and audio.
6. Run draft validation, perform the six editorial reviews, record their evidence
   and fingerprint, then validate/compile. These are production checks by the
   editor, not approval prompts to the user.

```bash
python3 premium_pipeline/v3/pipeline.py validate path/to/project.json --draft
python3 premium_pipeline/v3/pipeline.py fingerprint path/to/project.json
python3 premium_pipeline/v3/pipeline.py validate path/to/project.json
python3 premium_pipeline/v3/pipeline.py plan path/to/project.json --encoder libopenh264
```

`--draft` skips review records only for validate. It cannot bypass plan/render
gates. Structural errors, missing files, evidence mismatches, bad times and
unsafe crops still fail. Reviews do not alter the fingerprint; project content
and SHA256 of all assets/voice/alignment do. No command automatically passes reviews.

Only when the user actually requests video production in a future run:

```bash
python3 premium_pipeline/v3/pipeline.py render path/to/project.json --encoder h264_nvenc
python3 premium_pipeline/v3/pipeline.py qc path/to/project.json
```

Render outputs `build/draft.mp4`. FFmpeg refuses to overwrite it. Use a new
project/version directory for subsequent renders. Encoder choices: libopenh264
(portable installed CPU default here), h264_nvenc (requires a working NVIDIA
encoder), libx264 (requires an FFmpeg build with it). Failure is explicit; no
silent encoder fallback. Hardware presence must be checked before selecting it.

## Manifest field reference

All fields listed in `schema.py` are required; unknown fields are rejected.
All times are seconds except fields ending in `_frame`, which are integer
output frames. Word ranges are inclusive zero-based indices.

| Record | Meaning |
| --- | --- |
| asset | Unique id, local path, video/audio kind, source URL or original-recording provenance, rights note, observations |
| observation | Unique id within asset; exact source interval; literal subject/action labels; continuity session; concrete inspection detail; inspected boolean |
| beat | Aligned first/last word; role; claim; subject/action labels matching the inspected evidence; fact source/reference |
| shot | Unique id; asset/observation; contiguous output frames; source in; 0.5–2 speed; even source-pixel crop; >=3 subject/action boxes; supported beat IDs; editorial purpose; source-audio gain |
| caption | Word first/last; x/y center on 1080×1920 canvas; font size. Text and times come from alignment, not model estimates |
| audio | Asset, music/foley role, exact output frames, source in, dB gain and motivation. No auto-loop or auto-time-stretch |
| review | Criterion, passed boolean, reviewer, concrete evidence (>=40 chars) and current fingerprint |

Example records (illustrative, not verified assets):

```json
{
  "id":"S01", "asset":"A01", "observation":"O01",
  "start_frame":0, "end_frame":90, "source_in":4.0, "speed":1.0,
  "crop":[420,0,1080,1920],
  "subject_boxes":[[500,400,600,800],[520,400,600,800],[530,400,600,800]],
  "beat_ids":["B01"], "purpose":"Show the actual opening comparison",
  "production_gain_db":-12
}
```

Set `production_gain_db=-96` to explicitly disable a silent/unwanted source
audio track. Use the same subject/action label only when the observation
actually establishes the same thing. `continuity` is a real session/batch ID,
not an arbitrary value added to placate the checker. A demonstration requires
one continuity session; comparisons/explanations may use multiple with review.

The crop is static by design. There is no random zoom, mandatory flash, HUD,
color grade or cut quota. Subject boxes cover the action, not merely the food's
center. Keep required hands/tools inside the crop. Per-shot dynamic tracking,
animated explanatory diagrams and automatic semantic recognition are not
implemented; use explicitly prepared source assets when those are essential.

## What the checks guarantee—and don't

Implemented: strict shape, known IDs, asset presence/probes, positive contiguous
frame timeline, source bounds, observed-range bounds, subject/action consistency,
full temporal coverage of every speech beat, transcript agreement, word order,
caption estimates, conservative placement, actual crop geometry, silent-audio
handling, stale-review invalidation, and post-render decode/duration/loudness QC.

Not automatic: truthful object recognition, factual correctness of prose, good
acting, continuous tracking, exact glyph bounds, mobile UI detection, listener
comprehension or ranking prediction. Mandatory reviews cover those limitations.
An editor can falsify JSON; this is an auditable workflow, not a truth detector.

Compilation uses exact shot lengths and `atempo` for source audio; narration
is one unchanged take. Source sound and effects share a modest ducked bed.
Loudness normalization is a starting point and final AAC is remeasured. No media
claim is proven by an added sound effect. Review `draft.mp4` and write
`FINAL_REVIEW.md` tied to its SHA256 before calling it finished.

## Verification

```bash
python3 -m unittest discover -s premium_pipeline/v3/tests -v
```

Tests use metadata fixtures and command compilation; they create no video. This
implementation has not been end-to-end video-rendered in this task, respecting
the user's explicit instruction. Future render/QC still must be completed.
